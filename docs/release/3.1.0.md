## FDM-1254 native smoke checklist

Run this on a real Omarchy desktop after this pull request is merged. A prior
green run does not qualify a different SHA. Do not run the standalone dock and
the plugin host at the same time. If `dockrail dev use` is active, run
`dockrail dev reset` before any `omarchy plugin update` or `omarchy plugin remove`.

Record the desktop before installing:

```bash
git rev-parse HEAD
cat /usr/share/omarchy/version
pacman -Q omarchy hyprland quickshell
hyprctl version
command -v herdr >/dev/null && herdr --version || echo 'herdr: not installed'
command -v t3 >/dev/null && t3 --version || echo 't3: not installed'
command -v google-chrome-stable >/dev/null && google-chrome-stable --version || echo 'chrome: not installed'
```

Stop if `git rev-parse HEAD` is not the merged release commit.

From that same checkout:

```bash
omarchy plugin validate .
qmllint -I "$OMARCHY_PATH/shell" Overlay.qml Service.qml
qmllint -I "$OMARCHY_PATH/shell" \
  Overlay.qml DockHost.qml components/Dock.qml components/DockItem.qml \
  components/DockContextMenu.qml components/DockControlItem.qml \
  components/DockWindowActions.qml shell.qml Service.qml
```

The first `qmllint` line is the FDM-1254 minimum. The second line is the
repository entry-point set. `Service.qml` is a manifest entry point, so it is
included.

Back up `~/.config/dockrail` (and legacy `~/.config/smartdock` if it exists).
On a clean account or guest, install the Git-managed plugin and the CLI:

```bash
omarchy plugin add https://github.com/fernandodamaso/dockrail.git --enable --yes
git -C ~/.config/omarchy/plugins/io.github.fernandodamaso.dockrail rev-parse HEAD
bash ~/.config/omarchy/plugins/io.github.fernandodamaso.dockrail/install.sh --cli-only
dockrail setup
dockrail doctor
```

Stop if the installed `HEAD` is not the release commit. If
`XDG_CONFIG_HOME` is set, Omarchy's plugin commands still use
`$HOME/.config/omarchy/plugins`; use that path, not the XDG override.

Confirm one Quickshell host, a working dock and sidebar, and no second
standalone dock:

```bash
pgrep -a -f '(^|/)qs( |$)' || true
pgrep -a quickshell || true
```

Then exercise, on that one host:

- `omarchy plugin disable io.github.fernandodamaso.dockrail`
- `omarchy plugin enable io.github.fernandodamaso.dockrail`
- `omarchy restart shell`
- a theme switch
- workspace and window focus
- drag and menu controls
- a second monitor, when one is attached

Missing Herdr, T3, or Chrome must not stop the basic dock. `dockrail doctor`
should describe each unavailable capability.

Update, then reload the shell. Plugin update does not restart Quickshell:

```bash
omarchy plugin update io.github.fernandodamaso.dockrail --yes
omarchy restart shell
dockrail doctor
```

Confirm CLI metadata still matches the plugin and that
`~/.config/dockrail/dock.json` is unchanged apart from anything you edited
on purpose.

Remove the plugin and confirm settings remain:

```bash
omarchy plugin remove io.github.fernandodamaso.dockrail --yes
test ! -e ~/.config/omarchy/plugins/io.github.fernandodamaso.dockrail
test -f ~/.config/dockrail/dock.json
omarchy restart shell
```

The shell should still run. Plugin files are gone. User settings, shared
Widget packages, optional providers, and migration snapshots stay.

Standalone mode, only after the plugin is removed:

```bash
git clone https://github.com/fernandodamaso/dockrail.git
cd dockrail
git rev-parse HEAD
./install.sh
dockrail doctor
dockrail uninstall
test -f "${XDG_CONFIG_HOME:-$HOME/.config}/dockrail/dock.json"
```

`dockrail uninstall --purge` is a separate opt-in. It refuses while either
Dockrail plugin id is still installed. Do not combine it with the plugin
removal check above.

## Security preflight (FDM-1255)

The marketplace baseline is a static pattern check, not a security audit.
On 2026-11-20 `runSecurityBaseline` from
`omacom/omarchy-plugin-marketplace` `826d2b17a6b7f4bf818a573b75e77e7d8ca4885c`
(baseline version 3) was run against this branch's GitHub snapshot.
`docs/` and `tests/` are outside that scan. `blocksApproval` was false.
Result:

- outcome: `review-required`
- findings: none (`needs-fixes` patterns were not present)
- capabilities: `installer`, `remote-build`, `privilege`, `package-manager`, `service-management`

Expected evidence:

| Capability | Why it is present | What actually runs |
| --- | --- | --- |
| `installer` | `install.sh`, `uninstall.sh`, `scripts/install-browser-profile-provider` | User-directory install and removal. Not started by the plugin host. |
| `remote-build` | README tells standalone users to `git clone` this repository and run `./install.sh` | The clone is this same repository. No third-party unpinned build. |
| `privilege` and `package-manager` | `scripts/smartdock_cli.py` prints `sudo pacman -S --needed cmake gcc qt6-base` when launcher-count build tools are missing | The CLI prints the command. It does not run `sudo` or `pacman`. |
| `service-management` | `scripts/dev_session.py` contains `systemctl enable --now seatd` inside contributor KVM cloud-init, and `systemctl is-active seatd` in the guest SSH check | Not imported or executed by `Overlay.qml`, `Service.qml`, or `install.sh`. |

Default install behavior:

- `./install.sh` copies the standalone dock into XDG data/bin/application directories, creates `dock.json` only when that file is absent, and enables an XDG autostart entry. It does not call `sudo`, download anything, or write outside those user directories.
- `./install.sh --no-autostart` skips the autostart entry.
- `./install.sh --cli-only` installs the client and offline docs. It does not install a dock, write `dock.json`, or enable autostart.
- `./install.sh --agent-assets-only` installs terminal-agent launchers and icons and leaves foreign or edited files in place.
- `uninstall.sh` removes the standalone deployment and preserves configuration. `--purge` also removes Dockrail configuration, and it refuses before deleting anything while the Omarchy plugin is installed.
- `omarchy plugin remove` removes the plugin checkout and leaves `~/.config/dockrail` in place.
- Optional browser-profile and launcher-badge providers install only when their scripts are run by hand, under `$XDG_DATA_HOME/dockrail/providers`.

No `curl | bash`, `wget | bash`, unpinned `cargo install --git`, or passwordless sudoers policy was found in the scanned tree.

`preview.png` is a 1360×824 PNG (about 1.3 MB, about 1.1 megapixels), inside the marketplace limits of 50 MB and 40 megapixels. It shows the classic dock on a desktop wallpaper. The plugin id `io.github.fernandodamaso.dockrail` was not present in marketplace `registry.json` on 2026-11-20, including `retiredPluginIds`.

`omarchy` and `qmllint` are not installed in the release-prep environment. The structural checks from `omarchy-plugin-validate` at Omarchy `ff6533ee8f8193bc181751fefb6182e9a7bffb93` passed on this tree: schemaVersion 1, required fields, id outside `omarchy.*`, overlay and service entry points present, no symlinks outside `.git`.

### Maintainer notes

Dockrail 3.1.0 is an overlay and service plugin: a developer workspace rail for Hyprland (apps, windows, workspaces, widgets, and optional coding-agent sessions). It runs inside the existing Omarchy shell and does not start a second Quickshell process.

Plugin ID: io.github.fernandodamaso.dockrail. Category: Developer Tools. Tags: hyprland, quickshell, workspaces. Root preview: preview.png.

Settings live in ~/.config/dockrail/dock.json. First start migrates legacy SmartDock state through a journaled transaction and does not overwrite an existing Dockrail configuration. omarchy plugin remove leaves that configuration in place. uninstall.sh --purge is explicit and refuses while the plugin is installed.

install.sh, uninstall.sh, and scripts/install-browser-profile-provider are user-directory installers. They are not run by the plugin host. scripts/dev_session.py is a contributor-only KVM harness. Its systemctl seatd lines run inside that guest, not in the installed plugin.
